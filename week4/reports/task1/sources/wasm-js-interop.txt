1: Interoperability with JavaScript
2: 
3: Kotlin/Wasm allows you to use both JavaScript code in Kotlin and Kotlin code in JavaScript.
4: 
5: As with Kotlin/JS , the Kotlin/Wasm compiler also has interoperability with JavaScript. If you are familiar with Kotlin/JS interoperability, you can notice that Kotlin/Wasm interoperability is similar. However, there are key differences to consider.
6: 
7: Kotlin/Wasm is Beta . It may be changed at any time. Use it in scenarios before production. We would appreciate your feedback in YouTrack .
8: 
9: Use JavaScript code in Kotlin
10: 
11: Learn how to use JavaScript code in Kotlin by using external declarations, functions with JavaScript code snippets, and the @JsModule annotation.
12: 
13: External declarations
14: 
15: External JavaScript code is not visible in Kotlin by default. To use JavaScript code in Kotlin, you can describe its API with external declarations.
16: 
17: JavaScript functions
18: 
19: Consider this JavaScript function:
20: 
21: function greet (name) {
22:     console.log("Hello, " + name + "!");
23: }
24: 
25: You can declare it in Kotlin as an external function:
26: 
27: external fun greet(name: String)
28: 
29: External functions don't have bodies, and you can call it as a regular Kotlin function:
30: 
31: fun main() {
32:     greet("Alice")
33: }
34: 
35: JavaScript properties
36: 
37: Consider this global JavaScript variable:
38: 
39: let globalCounter = 0;
40: 
41: You can declare it in Kotlin using external var or val properties:
42: 
43: external var globalCounter: Int
44: 
45: These properties are initialized externally. The properties can't have = value initializers in Kotlin code.
46: 
47: JavaScript classes
48: 
49: Consider this JavaScript class:
50: 
51: class Rectangle {
52:     constructor (height, width) {
53:         this.height = height;
54:         this.width = width;
55:     }
56: 
57:     area () {
58:         return this.height * this.width;
59:     }
60: }
61: 
62: You can use it in Kotlin as an external class:
63: 
64: external class Rectangle(height: Double, width: Double) : JsAny {
65:     val height: Double
66:     val width: Double
67:     fun area(): Double
68: }
69: 
70: All declarations inside the external class are implicitly considered external.
71: 
72: External interfaces
73: 
74: You can describe the shape of a JavaScript object in Kotlin. Consider this JavaScript function and what it returns:
75: 
76: function createUser (name, age) {
77:     return { name: name, age: age };
78: }
79: 
80: See how its shape can be described in Kotlin with an external interface User type:
81: 
82: external interface User : JsAny {
83:     val name: String
84:     val age: Int
85: }
86: 
87: external fun createUser(name: String, age: Int): User
88: 
89: External interfaces don't have runtime type information and are a compile-time-only concept. Therefore, external interfaces have some restrictions compared to regular interfaces:
90: 
91: You can't use them on the right-hand side of is checks.
92: 
93: You can't use them in class literal expressions (such as User::class ).
94: 
95: You can't pass them as reified type arguments.
96: 
97: Casting with as to external interfaces always succeeds.
98: 
99: External objects
100: 
101: Consider these JavaScript variables holding an object:
102: 
103: let Counter = {
104:     value: 0,
105:     step: 1,
106:     increment () {
107:         this.value += this.step;
108:     }
109: };
110: 
111: You can use them in Kotlin as an external object:
112: 
113: external object Counter : JsAny {
114:     fun increment()
115:     val value: Int
116:     var step: Int
117: }
118: 
119: External type hierarchy
120: 
121: Similar to regular classes and interfaces, you can declare external declarations to extend other external classes and implement external interfaces. However, you can't mix external and non-external declarations in the same type hierarchy.
122: 
123: Callable JavaScript objects with @nativeInvoke
124: 
125: You can use the @nativeInvoke annotation on a Kotlin member function of an external declaration (a class or an interface) to make it callable as a JavaScript function.
126: 
127: With this annotation, each call to that function in Kotlin translates to a direct call to the JavaScript object:
128: 
129: import kotlin.js.nativeInvoke
130: 
131: @OptIn(ExperimentalWasmJsInterop::class)
132: external class JsAction {
133:     @nativeInvoke
134:     operator fun invoke(data: String)
135: }
136: 
137: fun main() {
138:     val action = JsAction() 
139:     action("Run task")
140: }
141: 
142: The @nativeInvoke annotation is a temporary solution until there's a design for stable interoperability. Currently, when you use @nativeInvoke , the compiler reports a warning.
143: 
144: Kotlin functions with JavaScript code
145: 
146: You can add a JavaScript snippet to Kotlin/Wasm code by defining a function with = js("code") body:
147: 
148: fun getCurrentURL(): String =
149:     js("window.location.href")
150: 
151: If you want to run a block of JavaScript statements, surround your code inside the string with curly brackets {} :
152: 
153: fun setLocalSettings(value: String): Unit = js(
154:     """{
155:         localStorage.setItem('settings', value);
156: }"""
157: )
158: 
159: If you want to return an object, surround the curly brackets {} with parentheses () :
160: 
161: fun createJsUser(name: String, age: Int): JsAny =
162:     js("({ name: name, age: age })")
163: 
164: Kotlin/Wasm treats calls to the js() function in a special way, and the implementation has some restrictions:
165: 
166: A js() function call must be provided with a string literal argument.
167: 
168: A js() function call must be the only expression in the function body.
169: 
170: The js() function is only allowed to be called from package-level functions.
171: 
172: The function return type must be provided explicitly.
173: 
174: Types are restricted, similar to external fun .
175: 
176: The Kotlin compiler puts the code string into a function in the generated JavaScript file and imports it into WebAssembly format. The Kotlin compiler doesn't verify these JavaScript snippets. If there are JavaScript syntax errors, they are reported when you run your JavaScript code.
177: 
178: The @JsFun annotation has similar functionality and will likely be deprecated.
179: 
180: JavaScript modules
181: 
182: By default, external declarations correspond to the JavaScript global scope. If you annotate a Kotlin file with the @JsModule annotation , then all external declarations within it are imported from the specified module.
183: 
184: Consider this JavaScript code sample:
185: 
186: // users.mjs
187: export let maxUsers = 10;
188: 
189: export class User {
190:     constructor (username) {
191:         this.username = username;
192:     }
193: }
194: 
195: Use this JavaScript code in Kotlin with the @JsModule annotation:
196: 
197: // Kotlin
198: @file:JsModule("./users.mjs")
199: 
200: external val maxUsers: Int
201: 
202: external class User : JsAny {
203:     constructor(username: String)
204: 
205:     val username: String
206: }
207: 
208: Array interoperability
209: 
210: You can copy JavaScript's JsArray<T> into Kotlin's native Array or List types; likewise, you can copy these Kotlin types to JsArray<T> .
211: 
212: To convert JsArray<T> to Array<T> or the other way around, use one of the available adapter functions .
213: 
214: Here's an example of conversion between generic types:
215: 
216: val list: List<JsString> =
217:     listOf("Kotlin", "Wasm").map { it.toJsString() }
218: 
219: // Uses .toJsArray() to convert List or Array to JsArray
220: val jsArray: JsArray<JsString> = list.toJsArray()
221: 
222: // Uses .toArray() and .toList() to convert it back to Kotlin types 
223: val kotlinArray: Array<JsString> = jsArray.toArray()
224: val kotlinList: List<JsString> = jsArray.toList()
225: 
226: Similar adapter functions are available for converting typed arrays to their Kotlin equivalents (for example, IntArray and Int32Array ). For detailed information and implementation, see the kotlinx-browser repository .
227: 
228: Here's an example of conversion between typed arrays:
229: 
230: import org.khronos.webgl.*
231: 
232:     // ...
233: 
234:     val intArray: IntArray = intArrayOf(1, 2, 3)
235:     
236:     // Uses .toInt32Array() to convert Kotlin IntArray to JavaScript Int32Array
237:     val jsInt32Array: Int32Array = intArray.toInt32Array()
238:     
239:     // Uses toIntArray() to convert JavaScript Int32Array back to Kotlin IntArray
240:     val kotlinIntArray: IntArray = jsInt32Array.toIntArray()

242: Use Kotlin code in JavaScript
243: 
244: Learn how to use your Kotlin code in JavaScript by using the @JsExport annotation.
245: 
246: Functions with the @JsExport annotation
247: 
248: To make a Kotlin/Wasm function available to JavaScript code, use the @JsExport annotation:
249: 
250: // Kotlin/Wasm
251: 
252: @JsExport
253: fun addOne(x: Int): Int = x + 1
254: 
255: Kotlin/Wasm functions marked with the @JsExport annotation are visible as properties on a default export of the generated .mjs module. You can then use this function in JavaScript:
256: 
257: // JavaScript
258: 
259: import exports from "./module.mjs"
260: 
261: exports.addOne(10)
262: 
263: The Kotlin/Wasm compiler is capable of generating TypeScript definitions from any @JsExport declarations in your Kotlin code. These definitions can be used by IDEs and JavaScript tools to provide code autocompletion, help with type-checks, and make it easier to consume Kotlin code from JavaScript and TypeScript.
264: 
265: The Kotlin/Wasm compiler collects any top-level functions marked with the @JsExport annotation and automatically generates TypeScript definitions in a .d.ts file.
266: 
267: To generate TypeScript definitions, in your build.gradle.kts file in the wasmJs{} block, add the generateTypeScriptDefinitions() function:
268: 
269: kotlin {
270:     wasmJs {
271:         binaries.executable()
272:         browser {
273:         }
274:         generateTypeScriptDefinitions()
275:     }
276: }
277: 
278: Generating TypeScript declaration files in Kotlin/Wasm is Experimental . It may be dropped or changed at any time.
279: 
280: Type correspondence
281: 
282: Kotlin/Wasm allows only certain types in signatures of JavaScript interop declarations. These limitations apply uniformly to declarations with external , = js("code") or @JsExport .
283: 
284: See how Kotlin types correspond to JavaScript types:
285: 
286: Kotlin | JavaScript
287: Byte , Short , Int , Char , UByte , UShort , UInt , | Number
288: Float , Double , | Number
289: Long , ULong , | BigInt
290: Boolean , | Boolean
291: String , | String
292: Unit in return position | undefined
293: Function type, for example (String) -> Int | Function
294: JsAny and subtypes | Any JavaScript value
295: JsReference | Opaque reference to Kotlin object
296: Other types | Not supported
297: 
298: You can use nullable versions of these types as well.
299: 
300: JsAny type
301: 
302: JavaScript values are represented in Kotlin using the JsAny type and its subtypes.
303: 
304: The Kotlin/Wasm standard library provides representation for some of these types:
305: 
306: Package kotlin.js :
307: 
308: JsAny
309: 
310: JsBoolean , JsNumber , JsString
311: 
312: JsArray
313: 
314: Promise
315: 
316: You can also create custom JsAny subtypes by declaring an external interface or class.
317: 
318: JsReference type
319: 
320: Kotlin values can be passed to JavaScript as opaque references using the JsReference type.
321: 
322: For example, if you want to expose this Kotlin class User to JavaScript:
323: 
324: class User(var name: String)
325: 
326: You can use the toJsReference() function to create JsReference<User> and return it to JavaScript:
327: 
328: @JsExport
329: fun createUser(name: String): JsReference<User> {
330:     return User(name).toJsReference()
331: }
332: 
333: These references aren't directly available in JavaScript and behave like empty frozen JavaScript objects. To operate on these objects, you need to export more functions to JavaScript using the get() method where you unwrap the reference value:
334: 
335: @JsExport
336: fun setUserName(user: JsReference<User>, name: String) {
337:     user.get().name = name
338: }
339: 
340: You can create a class and change its name from JavaScript:
341: 
342: import UserLib from "./userlib.mjs"
343: 
344: let user = UserLib.createUser("Bob");
345: UserLib.setUserName(user, "Alice");
346: 
347: Type parameters
348: 
349: JavaScript interop declarations can have type parameters if they have an upper bound of JsAny or its subtypes. For example:
350: 
351: external fun <T : JsAny> processData(data: JsArray<T>): T
352: 
353: Exception handling
354: 
355: You can use Kotlin try-catch expressions to catch JavaScript exceptions in Kotlin/Wasm code. Exception handling works as follows:
356: 
357: Exceptions thrown from JavaScript: detailed information is available on the Kotlin side. If such an exception propagates back to JavaScript, it's no longer wrapped into WebAssembly.
358: 
359: Exceptions thrown from Kotlin: they can be caught on JavaScript's side as regular JS errors.
360: 
361: Here's an example that demonstrates catching a JavaScript exception on the Kotlin side:
362: 
363: external object JSON {
364:     fun <T: JsAny> parse(json: String): T
365: }
366: 
367: fun main() {
368:     try {
369:         JSON.parse("an invalid JSON")
370:     } catch (e: JsException) {
371:         println("Thrown value is: ${e.thrownValue}")
372:         // SyntaxError: Unexpected token 'a', "an invalid JSON" is not valid JSON
373: 
374:         println("Message: ${e.message}")
375:         // Message: Unexpected token 'a', "an invalid JSON" is not valid JSON
376: 
377:         println("Stacktrace:")
378:         // Stacktrace:
379: 
380:         // Prints the full JavaScript stack trace 
381:         e.printStackTrace()
382:     }
383: }
384: 
385: This exception handling works automatically in modern browsers that support the WebAssembly.JSTag feature:
386: 
387: Chrome 115+
388: 
389: Firefox 129+
390: 
391: Safari 18.4+

393: Kotlin/Wasm and Kotlin/JS interoperability differences
394: 
395: Although Kotlin/Wasm interoperability shares similarities with Kotlin/JS interoperability, there are key differences to consider:
396: 
397:  | Kotlin/Wasm | Kotlin/JS
398: External enums | Doesn't support external enum classes. | Supports external enum classes.
399: Type extensions | Doesn't support non-external types to extend external types. | Supports non-external types.
400: JsName annotation | Only has an effect when annotating external declarations. | Can be used to change names of regular non-external declarations.
401: js() function | js("code") function calls are allowed as a single expression body of package-level functions. | The js("code") function can be called in any context and returns a dynamic value.
402: Module systems | Supports ES modules only. There is no analog of the @JsNonModule annotation. Provides its exports as properties on the default object. Allows exporting package-level functions only. | Supports ES modules and legacy module systems. Provides named ESM exports. Allows exporting classes and objects.
403: Types | Applies stricter type restrictions uniformly to all interop declarations external , = js("code") , and @JsExport . Allows a select number of built-in Kotlin types and JsAny subtypes . | Allows all types in external declarations. Restricts types that can be used in @JsExport .
404: Long | Type corresponds to JavaScript BigInt . | Visible as a custom class in JavaScript.
405: Arrays | Not supported in interop directly yet. You can use the new JsArray type instead. | Implemented as JavaScript arrays.
406: Other types | Requires JsReference<> to pass Kotlin objects to JavaScript. | Allows the use of non-external Kotlin class types in external declarations.
407: Exception handling | You can catch any JavaScript exception with the JsException and Throwable types. | Can catch JavaScript Error using the Throwable type. It can catch any JavaScript exception using the dynamic type.
408: Dynamic types | Does not support the dynamic type. Use JsAny instead (see sample code below). | Supports the dynamic type.
409: 
410: Kotlin/JS dynamic type for interoperability with untyped or loosely typed objects is not supported in Kotlin/Wasm. Instead of the dynamic type, you can use the JsAny type:
411: 
412: // Kotlin/JS
413: fun processUser(user: dynamic, age: Int) {
414:     // ...
415:     user.profile.updateAge(age)
416:     // ...
417: }
418: 
419: // Kotlin/Wasm
420: private fun updateUserAge(user: JsAny, age: Int): Unit =
421:     js("{ user.profile.updateAge(age); }")
422: 
423: fun processUser(user: JsAny, age: Int) {
424:     // ...
425:     updateUserAge(user, age)
426:     // ...
427: }

429: Web-related browser APIs
430: 
431: The kotlinx-browser library is a standalone library that provides JavaScript browser APIs, including:
432: 
433: Package org.khronos.webgl :
434: 
435: Typed arrays, like Int8Array .
436: 
437: WebGL types.
438: 
439: Packages org.w3c.dom.* :
440: 
441: DOM API types.
442: 
443: Package kotlinx.browser :
444: 
445: DOM API global objects, like window and document .
446: 
447: To use the declarations from the kotlinx-browser library, add it as a dependency in your project's build configuration file:
448: 
449: val wasmJsMain by getting {
450:     dependencies {
451:         implementation("org.jetbrains.kotlinx:kotlinx-browser:0.3")
452:     }
453: }
